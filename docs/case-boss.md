# 案例：把 BOSS 直聘接成第一个适配器

第一个真实适配器选 BOSS 直聘，不是因为它最好接，而是因为它的页面结构最"刁"——把最难的那个先做通，剩下的平台都是同一套动作换选择器。

这份文档记录的是**实际踩过的坑**，不是从文档抄的步骤。所有坐标和选择器都会随平台改版失效，价值在于"该往哪儿找"。

> 状态：流程已人工跑通（附件上传、6 步引导、6 条经历同步落库），下面的参考实现尚未在 CI 环境实测。选择器需按当前页面校准。

---

## 1. 整体路径

BOSS 的简历完善分两段，顺序不能反：

```
附件上传解析  →  6 步引导（补基础信息）  →  导入已有简历（补工作经历）
```

先走引导：引导没走完，简历页是锁的。引导走完才出现「导入已有简历」入口。

## 2. 六个坑

### 坑 1：视口高度不够，点击"静默失败"

`dispatchMouseEvent` 打不到视口外的坐标——不报错，没有任何反应，看起来像选择器错了。

- 「保存至在线简历」按钮在 y≈1035，视口 920 高时永远点不中。
- 解决：把视口拉到 1200 高（`page.set_viewport_size({"width": 1580, "height": 1200})`）。
- 通用做法：**每次点击前取 `getBoundingClientRect()` 判断 y 是否在视口内**，不在就先滚动，不要用写死的坐标。

### 坑 2：表单随滚动位移，写死坐标必挂

引导过程中表单会随滚动上移，同一个 input 的中心从 y=461 漂到 y=270。早期脚本按首屏坐标写死，全部落空。

规则：**每一步都重新取 rect，不要缓存坐标**。

### 坑 3：日期面板一屏只显示十年

出生年月默认显示「2000 - 2009年」。目标 1985 在上一页。

- 翻页箭头 `span.prev` 尺寸只有 40×30，被输入框视觉压住，常规定位点不到。
- 实测要连点两次：`2000-2009` → `1990-1999` → `1980-1989`。
- 年份格 `div.cell.year`，选中态带 `selected`；月份面板是另一层 `div.cell.month`。
- 年份格和月份格在**同一坐标**但属于不同面板——点完年份要等月份面板真正出现再点，否则会点到上一层的残留，出现 `1985-06` 这种错值。

### 坑 4：城市是三级联动，前两列不落值

期望城市不是选「浙江→台州」就完事：

1. 省份列 `ul.ui-dropdown-list` 要滚到 `scrollTop=700` 才看得到「浙江」
2. 点「浙江」后出现二级城市列
3. 点「台州」后出现**第三列区县**：台州 / 温岭市 / 临海市 / 玉环市
4. 必须点第三列的「台州」叶子节点，值才真正落进表单

只点前两级，表单看着有值，提交后是空的。

### 坑 5：薪资是双列，不是单列

最低月薪和最高月薪是两个独立的 `ul`：

- 左列滚 `scrollTop=1260` 才命中 35k
- 右列直接点 55k（不需要滚）

### 坑 6：导入弹层不能用导航刷新

`lp.nav()` 是在**当前标签页**上导航，不是新开标签。在导入弹层打开时调用，整个「同步新的工作经历 1/6」弹层会被顶掉，只能重新触发一次解析（等 40-60 秒）。

规则：弹层打开期间，任何导航都不要做。

## 3. 附件导入 → 逐条落库

入口：简历页「导入已有简历」→ 弹层 `.resume-list li` 里能看到已上传的 PDF → 点 `.operate-list a`。

这个链接的 `rect` 是 `(0,0)`，视觉上被隐藏，**只能用 JS click**，鼠标事件点不到。

点完是「正在为您解析中…」，40-60 秒后弹出「同步新的工作经历 N/6」。

每条要点一次「保存至在线简历」，步骤计数从 1/6 走到 6/6。这个按钮就是坑 1 里那个 y≈1035 的按钮。

落库结果（实测）：

- 工作经历 5 段，时间连续无断档
- 「代理总监（年度轮值）」和「XC70 新车型导入」被系统自动归到**项目经历**，没有污染工作经历

## 4. 落库后必须核对

不要相信"点了 6 次保存"就等于 6 条都进去了。核对三件事：

1. **段数**：工作经历应该是 5 段（不是 1 段，也不是 6 段）
2. **时间连续性**：相邻两段的起止月份要接得上，中间不能有断档
3. **项目经历隔离**：轮值/项目类条目不能出现在工作经历里

写个只读脚本读简历页正文，按 `公司名 + 起止时间` 逐条比对，比截图可靠。

## 5. 已知遗留（真实项目都会有的部分）

这三条是跑通之后留下的瑕疵，写在这里是因为**它们比成功路径更有参考价值**：

| 问题 | 原因 | 修法 |
|---|---|---|
| 东风那条职位名是「工艺工程师」，实际是质量主管 | 附件解析按岗位关键词猜的 | 进单条编辑器改 |
| 北汽 2011-2019 那条是「质量管理/测试工程师」，实际是质量经理 | 同上 | 同上 |
| 沃尔沃那条行业写成「工程施工」 | 行业字段解析错 | 同上 |

结论：**解析出来的职级和行业不可信，必须人工过一遍**。所以适配器里 `apply` 之外的一切都应该是只读的，改简历这种动作永远留给人。

## 6. 参考实现要点

`adapters/boss/adapter.py` 里体现的约定：

- `open()` 用 `connect_over_cdp` 接管已登录的 Edge，不做登录
- `health()` 检查三个东西：登录头像、职位列表容器、投递按钮
- `search()` 只读列表，`job_id` 取自详情页 URL 的末段
- `apply()` 点完必须等「已投递」状态出现，等不到就返回 `FAILED`，不要自欺
- 出现滑块/验证码 → `NEEDS_HUMAN`，整个适配器暂停
