# job-copilot · 求职投递编排器

把「每天在 N 个招聘平台重复投简历」变成一条**可审计、可限速、可中断续跑**的流水线。

这个项目不帮你投得更多，它帮你投得**不重复、不失控、可复盘**。

> 现状：接口层与编排层已完成（dry-run 可跑通），平台适配器只提供空模板。你需要自己接一个平台，本项目不代管任何账号。

---

## 它解决什么问题

手动海投的真实成本不在「点按钮」，在这四件事：

1. **重复投**：同一个岗位今天投过、上周投过，平台不拦，你也不知道，白耗掉机会额度。
2. **失控**：一口气点 200 个，第二天账号被限流或直接风控，之前的投递全废。
3. **不可复盘**：投了多少、哪些公司、哪些渠道来的面试，全在脑子里，一周后就说不清了。
4. **中断即重来**：脚本崩了、电脑睡了、网页刷新了，不确定哪条投成功、哪条没投，只能全量重投。

对应的四个设计：

| 问题 | 设计 |
|---|---|
| 重复投 | 三源去重：黑名单 → 历史台账 → 当日批内 |
| 失控 | 批大小 + 间隔抖动 + 日上限 + 连续失败熔断 |
| 不可复盘 | 投成即落盘，台账即战报，六项固定口径 |
| 中断即重来 | 先写意图（pending）再执行，崩溃后按证据核验，不盲投 |

---

## 明确不做的事

这几条写在这里，是为了让仓库的边界清晰，也为了让用它的人少踩坑：

- **不做「一键海投」**：默认日上限 50，超出需显式改配置。
- **不做账号池、不做多账号轮换**：一个适配器只服务一个已登录会话。
- **不做验证码识别、不做风控绕过**：遇到验证码一律转人工接管。
- **不内置密码与 Cookie**：登录由你在自己的浏览器里手动完成，程序只接管已登录会话。
- **不做简历内容生成或美化**：简历是你的事。
- **不保证平台接口稳定**：页面上线改版即失效，这是这类工具的常态。

使用前请自行确认目标平台的用户协议。自动化操作可能违反平台条款并导致账号受限，**风险由使用者承担**。

## 快速开始

```bash
git clone <this-repo> && cd job-copilot
python -m pip install -e .        # 只依赖 PyYAML

# 用内置 MockAdapter 跑一遍完整流水线（不访问任何网站）
python -m jobcopilot run --config config.example.yaml --dry-run

# 查看台账与当日战报
python -m jobcopilot report --config config.example.yaml
```

dry-run 会走完：加载配置 → 黑名单预热 → 模拟取岗 → 三源去重 → 按节奏模拟投递 → 幂等落盘 → 输出六项战报。
全程不产生网络请求，可以放心先跑这个。

## 接一个真实平台

1. 复制 `adapters/_template/` 到 `adapters/<platform>/`
2. 实现 `docs/adapter-contract.md` 里的 6 个方法
3. 在 `config.yaml` 的 `platforms` 下注册
4. 先用 `--dry-run` 跑，确认 `search()` 返回的岗位、去重结果、分页行为都符合预期
5. 再开真实投递，**首批只跑 3 个**，人工核对页面确实出现了投递记录

适配器是唯一允许有副作用的地方，其余层（编排、去重、台账、节奏）都不要碰。

## 目录结构

```
job-copilot/
├── config.example.yaml       # 全部参数，无个人数据
├── src/jobcopilot/
│   ├── models.py             # Job / ApplyResult / 台账行
│   ├── adapter.py            # 适配器协议与注册
│   ├── ledger.py             # 台账读写、三源去重、幂等
│   ├── pacing.py             # 限速、抖动、熔断
│   ├── runner.py             # 编排主循环
│   └── cli.py                # run / report
├── adapters/
│   ├── _template/            # 适配器模板
│   └── mock/                 # 离线演示用
└── docs/
```
